A3. Database cheat-sheet

Static tables: sys_companies (tenant master, licence/demo/lock), sys_users (role, permissions, linked customers, hide rates, bypass), sys_sessions (12-hour tokens), sys_counters (company/year voucher sequence).

Per-company dynamic tables: {code}_products, {code}_customers, {code}_master_ledger. The unified ledger stores all four voucher types: SALES_ORDER, GDN_GATE_PASS, SALES_TAX_INVOICE, BANK_RECEIPT.

Enums: roles SUPER_ADMIN / COMPANY_ADMIN / CUSTOMER / STORE_FG / ACCOUNTS; product type REGISTERED / UNREGISTERED; registration Register / Unregister; income tax Filer / Non Filer; statuses PENDING / PARTIAL_DELIVERED / DELIVERED / INVOICED / PARTIAL_PAID / PAID.

Core RPCs: app_authenticate, app_logout, session_user, is_super_admin, check_company, next_voucher_no, create_company, create_company_user, update_company_user, list_company_users, create_voucher, insert_master_ledger, sync_sales_order, import_company_data, change_own_password, update_company_settings, extend_company_demo, convert_company_to_full_license, factory_reset_company.

Triggers/logic: product stock init, ledger stock (only GDN moves stock), sales-order sync, ledger insert/mutation guards, company profile super-admin guard, tax-rate defaults, user defaults.

A4. Security architecture

  • Custom session token stored in localStorage and sent as x-ozone-session; Supabase Auth sessions are disabled.
  • RLS + SECURITY DEFINER functions enforce company isolation and voucher-type permissions; the UI mirrors, but does not replace, database checks.
  • Three lock layers: company (inactive/demo expired/licence expired), voucher (3-day, cutoff date, downstream record), desktop (expired lock file + offline screen).
  • Confidential playbook is fetched from /api/founder-playbook, which re-verifies is_super_admin() server-side before returning content; never bundle it into client JS.
  • Seed demo credentials in supabase/erp/04_seed.sql must be rotated before any real client handover.

A5. Deploy / build commands

  • npm run lint → tsc --noEmit; npm run build → Next production build.
  • npx vercel --prod --yes → production deploy to ozoneso.vercel.app.
  • npm run dist → NSIS installer at release/OZONE-Enterprise-Setup-1.0.0.exe.
  • npm run electron:build:company -- --company=CODE --expiry=YYYY-MM-DD --name="Company Name" → company-locked installer.

Part B — Target Industry, Value Proposition & Client Lead Generation Blueprint

B1. Who needs this software

  • Core ICP: diaper, baby-care and FMCG distributors/wholesalers in Pakistan managing cartons, pieces, bookers and tax invoices.
  • Cities: Karachi (first priority: SITE, Korangi, North Karachi, Gulistan-e-Johar industrial clusters), Lahore, Faisalabad, Islamabad/Rawalpindi, Multan, Peshawar; then GCC, UK and US small distributors.
  • Buyers: owner/founder, company admin, store manager, accounts manager, distributor booker.
  • Trigger events: paper registers losing money, GST/Section 23 invoice mistakes, stock discrepancies, 30+ day receivables, demo expiry of a competitor tool.

B2. Value proposition

  • One controlled chain from order to cash with automatic voucher numbers and tax.
  • Role-separated data: store cannot invoice, accounts cannot dispatch, customer sees only own orders and no rates.
  • Owner controls licences, demo days, suspension and factory reset without touching code.
  • Cloud web plus Windows desktop installer for branch-level usage.
  • Fast onboarding through CSV product/customer import and company wizard.

B3. Lead generation blueprint

  1. Facebook / LinkedIn demo funnel: post 45-second clips of order → GDN → invoice → receipt; CTA "Free 7-day OZONE demo on WhatsApp".
  2. WhatsApp free-trial onboarding: collect company name/code, product list and customer list; create demo company; send credentials + guide link; day-3 check-in; day-6 conversion call.
  3. Industrial area targeting: visit/phone distributors in Karachi SITE/Korangi and Lahore/Faisalabad wholesale markets; offer a 20-minute on-site stock-and-ledger audit.
  4. Referral loop: ask satisfied distributors for one peer introduction in exchange for extended demo days.
  5. Bukharihub advisory cross-sell: bundle ERP setup with process design, staff training, tax-workflow advisory and custom branding; sell implementation, not just a login.
  6. Retention: weekly aging report review, monthly backup/licence check, quarterly feature review.

B5. Client deployment / handover checklist

  1. Create company via Super Admin wizard; set code, name, expiry, owner contact and max users.
  2. Import products and customers CSV; verify opening stock and tax/filer flags.
  3. Create Company Admin, Store/FG, Accounts and linked Customer logins; rotate all seed credentials.
  4. Set company logo, bank details, NTN/STRN, address and entry lock date if required.
  5. Run one complete test: SO → GDN → Invoice → Receipt → Ledger → Aging → Print.
  6. Share the EN/UR master user guide; demonstrate Change Password and sign-out hygiene.
  7. Decide cloud-only vs desktop installer; for desktop, build company-locked setup.exe and test launch + print + offline retry.
  8. Record licence renewal date and WhatsApp support contact in the owner playbook.
